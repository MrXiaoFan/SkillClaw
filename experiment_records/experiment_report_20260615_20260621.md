# SkillClaw 漏洞定位实验阶段报告（2026-06-15 至 2026-06-21）

## 一、实验目标

本阶段实验目标是验证一个核心问题：SkillClaw 进化/沉淀出来的 server-side skill，是否能在 Claude Code + SkillClaw key 的使用方式下，实际提升漏洞定位能力。

实验不把“能看到 skill”作为最终目标，而是进一步检查：

1. SkillClaw 是否真的将相关 skill 注入到模型上下文。
2. 注入 skill 后，模型是否更容易命中真实漏洞文件和函数。
3. 命中结果是否能通过源码检查、二进制检查、脚本 checker 或后续 ASan/PoC 验证支撑。
4. SkillClaw 与同一上游 DeepSeek 直连相比，是否存在稳定优势或明显短板。

## 三、评分标准

本阶段采用 10 分制人工评分，并逐步引入脚本化 validator。评分项如下：

| 评分项 | 分值 | 判定标准 |
|---|---:|---|
| 文件定位 | 2 | 是否命中官方漏洞或补丁对应源文件 |
| 函数定位 | 2 | 是否命中官方漏洞或补丁对应函数 |
| 漏洞类型 | 1.5 | 是否正确判断 buffer over-read、OOB read、buffer overflow 等类型 |
| 根因与数据流 | 2 | 是否说明攻击者可控字段、边界检查缺失、数据流到危险访问点 |
| 证据质量 | 1.5 | 是否执行 grep、sed、readelf、objdump 等检查，并引用源码/二进制证据 |
| 输出纪律 | 1 | 是否遵守 JSON 输出、避免无关候选点发散和明显 CVE 幻觉 |

当前阶段人工评分仍然重要，因为原生 SkillClaw validation 主要是 replay/相似性验证，不能替代真实漏洞证据。后续通过 `experiment_validation` 框架逐步加入 source、bundle script、ASan/PoC 验证。

## 四、实验一：tcpdump-4.9.1 targeted 任务

### 4.1 任务设计

该任务明确提示目标区域：

```text
目标：定位 tcpdump 4.9.1 中与 IPv6 fragmentation header parser 相关的 buffer over-read 漏洞。
要求：不要 WebSearch；SkillClaw 组优先使用 server-side skill；DeepSeek 组不使用任何 skill；最终输出 JSON。
```

对应 ground truth：

```text
CVE：CVE-2017-13031
文件：print-frag6.c
函数：frag6_print
漏洞类型：buffer over-read / insufficient bounds check
官方描述要点：tcpdump 4.9.2 之前版本在 IPv6 fragmentation header parser 中存在 buffer over-read。
```

### 4.2 SkillClaw 组结果

模型定位结果：

```text
文件：print-frag6.c
函数：frag6_print
漏洞类型：buffer over-read / CWE-126
```

主要证据：

```text
检查了 print-frag6.c、print-ip6.c、ip6.h、netdissect.h。
执行了 readelf、objdump、grep、sed。
指出 ND_TCHECK(dp->ip6f_offlg) 与后续读取 ip6f_ident 的范围存在不一致。
```

人工评估：

```text
结果：成功定位文件和函数。
问题：最终 summary 中出现 CVE 编号错误，并且违反“最终只输出 JSON”的格式要求。
评分：7.5/10
```

### 4.3 DeepSeek 直连组结果

模型定位结果：

```text
文件：print-frag6.c
函数：frag6_print
漏洞类型：buffer over-read / insufficient bounds check
```

人工评估：

```text
结果：成功定位文件和函数。
优点：输出更收敛，CVE 幻觉问题较少。
不足：部分反汇编解释略不严谨。
评分：8.5/10
```

### 4.4 实验一结论

该任务提示已经接近答案，因此区分度不高。SkillClaw 和 DeepSeek 直连都能完成定位；严格评分下，DeepSeek 直连略优于 SkillClaw。

结论：

```text
tcpdump targeted 任务不能证明 SkillClaw 提升漏洞定位能力。
该任务反而提示我们：SkillClaw 注入 skill 后可能带来额外上下文噪声或 CVE 编号幻觉。
```

## 五、实验二：tcpdump-4.9.1 discovery 任务

### 5.1 任务设计

该任务不提示具体协议、文件、函数或 CVE，只要求模型从源码和二进制中定位一个已知内存越界漏洞。

```text
目标：定位 tcpdump 4.9.1 中一个已知内存越界漏洞。
要求：不要 WebSearch；不要依赖漏洞编号或公开描述；从源码和二进制证据出发。
```

### 5.2 SkillClaw 组结果

模型定位结果：

```text
文件：print-isakmp.c
函数：ikev1_n_print
漏洞类型：CWE-120 / CWE-823，实质方向接近 buffer over-read
对应公开漏洞方向：CVE-2018-14469
```

记录到的主要 server-side skills：

```text
elf-cwe120-static-scan
elf-cwe120-plt-analysis
elf-cwe120-firmware-triage
```

人工评估：

```text
结果：成功收敛到真实已知漏洞函数。
优点：未给出具体协议或文件时，仍能定位到 print-isakmp.c:ikev1_n_print。
不足：根因解释还需要补丁或 PoC 进一步验证；漏洞类型表述不够收敛。
评分：8.5/10
```

### 5.3 DeepSeek 直连组结果

模型定位结果：

```text
文件：print-isoclns.c
函数：isis_print_ext_is_reach
漏洞类型：buffer over-read via unvalidated packet-supplied length
```

人工评估：

```text
结果：部分成功。
说明：print-isoclns.c 是 tcpdump 4.9.1 已知漏洞高发文件，邻近 CVE 包括 CVE-2017-13055、CVE-2017-12998。
问题：最终函数与明确公开 ground truth 不完全对齐，候选路径更发散。
评分：6.5/10
```

### 5.4 实验二结论

该任务比 targeted 任务更有区分度。SkillClaw 组在没有文件/函数提示的情况下，输出更收敛，函数级定位优于 DeepSeek 直连。

结论：

```text
tcpdump discovery 任务中，SkillClaw 显示出一定正向效果。
但该结论仅来自单个项目和单轮实验，不能推广为统计显著结论。
```

## 六、实验三：libxml2-2.9.4 discovery 任务

### 6.1 任务设计

该任务用于检查 SkillClaw 是否能处理源码级 parser state-machine 漏洞，而不是只做 ELF/PLT/CWE-120 危险函数 triage。

```text
目标：定位 libxml2-2.9.4 中一个已知内存越界漏洞。
要求：不要 WebSearch；不提示具体 CVE、文件或函数；从源码和构建产物中定位最可能漏洞点。
```

主要参考 ground truth：

```text
CVE：CVE-2017-8872
文件：HTMLparser.c
函数：htmlParseTryOrFinish
漏洞类型：buffer over-read / out-of-bounds read
官方描述要点：libxml2 2.9.4 的 HTMLparser.c:htmlParseTryOrFinish() 存在 buffer over-read，可导致 DoS 或信息泄露风险。
```

### 6.2 原始 SkillClaw 组结果（34 skills）

模型定位结果：

```text
文件：HTMLparser.c
函数：htmlParseName
漏洞类型：Heap Buffer Over-read / CWE-126
```

主要观察：

```text
模型受到 elf-cwe120-static-scan / elf-cwe120-plt-analysis 类 skill 影响较强。
它发现了 valid.c 中 xmlSnprintfElementContent 相关危险信号，但没有继续追踪。
最终转向 HTMLparser.c/htmlParseName，未命中 htmlParseTryOrFinish。
```

人工评估：

```text
结果：partial / near miss。
评分：5/10
原因：命中文件族和漏洞类型方向，但函数错误，根因推理偏 speculative。
```

### 6.3 DeepSeek 直连组结果

模型定位结果：

```text
文件：HTMLparser.c
函数：htmlParseTryOrFinish
漏洞类型：Heap-based out-of-bounds read / buffer over-read
```

主要根因：

```text
在 XML_PARSER_EPILOG 等状态下，代码只检查 avail >= 2，
但后续访问 in->cur[2] 和 in->cur[3] 来判断 '<!--' 注释序列。
访问前没有验证 avail >= 4，导致越界读风险。
```

人工评估：

```text
结果：成功命中 CVE-2017-8872。
评分：9/10
不足：没有 PoC/补丁级验证，confidence 偏高。
```

### 6.4 实验三结论

libxml2 原始实验是 SkillClaw 的负样本。SkillClaw 被已有 ELF/PLT/CWE-120 skill 带偏，没有很好地覆盖源码级 parser state-machine 边界检查漏洞。

结论：

```text
SkillClaw 的效果强依赖 skill 与目标漏洞类型是否匹配。
当 skill 类型不匹配时，SkillClaw 可能弱于基础模型直连。
```

## 七、实验四：新增 source-parser-state-machine-oob skill 后的 libxml2 复测

### 7.1 新增 skill 目的

基于 libxml2 负样本，新增：

```text
source-parser-state-machine-oob
```

该 skill 目标是引导模型分析源码级 parser 状态机边界检查，重点关注：

```text
cur / end / avail
lookahead read
chunked parsing
if (avail < N) 与 buf[k] / cur[k] 访问之间是否匹配
```

新增后远端验证：

```text
SkillClaw server-side skill count = 35
source-parser-state-machine-oob visible = True
```

服务端注入审计记录显示：

```text
selected_skill_names = [
  "source-parser-state-machine-oob",
  "elf-cwe120-plt-analysis",
  "skillclaw-proxy-introspection"
]
injection_mode = inline
skill_prompt_hash = d9df1a2d2fc9402c
session_id = e85ef465-4a19-4b47-9d22-ab08205a19f4
```

### 7.2 复测结果

模型定位结果：

```text
文件：HTMLparser.c
函数：htmlParseTryOrFinish
关键访问：in->cur[2] / in->cur[3]
实际 guard：avail < 2
需要 guard：avail >= 4
可达路径：xmllint -> htmlReadMemory -> htmlParseChunk -> htmlParseTryOrFinish
```

人工评估：

```text
结果：命中关键函数和根因。
评分：约 8/10
```

加分点：

```text
1. 命中 HTMLparser.c / htmlParseTryOrFinish。
2. 明确指出 avail 与 in->cur[2]/in->cur[3] 不匹配。
3. 分析方向从 PLT 危险函数扫描转向源码级 parser 状态机。
4. 服务端记录证明 source-parser-state-machine-oob 被 inline 注入。
```

扣分点：

```text
1. CVE 编号映射仍然混乱。
2. 输出多个 finding，不够收敛。
3. 缺少 PoC、ASan 或补丁 diff 级验证。
4. retrieval 仍混入 elf-cwe120-plt-analysis，说明旧 skill 仍有干扰。
```

### 7.3 实验四结论

对比结果：

| 编号 | 任务 | 方式 | 输出文件/函数 | 结果 | 评分 |
|---|---|---|---|---|---:|
| L1 | libxml2 discovery | SkillClaw 原始 34 skills | HTMLparser.c / htmlParseName | 部分命中，函数错误 | 5/10 |
| L2 | libxml2 discovery | DeepSeek 直连 | HTMLparser.c / htmlParseTryOrFinish | 成功命中 CVE-2017-8872 | 9/10 |
| L3 | libxml2 discovery | SkillClaw + source-parser-state-machine-oob | HTMLparser.c / htmlParseTryOrFinish | 命中关键函数和根因，但 CVE 映射有误 | 8/10 |

结论：

```text
新增领域匹配 skill 后，SkillClaw 在 libxml2 任务中的表现从 5/10 提升到约 8/10。
这说明 SkillClaw 的 server-side inline 注入可以纠正分析路径，并提升漏洞定位质量。
但复测仍未超过 DeepSeek 直连的 9/10，主要问题是 CVE 映射、输出收敛和动态验证不足。
```

## 八、实验五：动态验证 MVP 框架自测

### 8.1 实验目的

前述实验主要依赖人工评分。为减少“只凭模型最终回答判断”的问题，本阶段开始搭建 case-level validation MVP。

目标不是实现通用漏洞验证平台，而是建立最小闭环：

```text
Agent 输出 -> ground truth 评分 -> source/binary/script/ASan validator -> feedback
```

### 8.2 已实现组件

新增目录：

```text
experiment_cases/
experiment_scripts/
experiment_validation/
tests/test_experiment_scripts.py
```

主要 validator：

```text
content_match：检查 Agent 输出是否命中 ground truth。
source_contains：检查源码文件中是否存在关键函数/模式。
command：执行普通命令验证环境或二进制。
bundle_script：运行 skill bundle 附带 checker。
asan_command：检查 ASan/UBSan/crash 输出是否命中 sanitizer marker 和目标栈。
```

## 十、阶段性结论

1. SkillClaw 不是稳定全面优于 DeepSeek 直连。tcpdump targeted 和 libxml2 原始实验都显示 SkillClaw 可能弱于基础模型。
2. SkillClaw 的价值更像“任务类型匹配时的分析路径引导”。tcpdump discovery 和 libxml2 新 skill 复测显示，当 skill 与目标漏洞类型匹配时，SkillClaw 可以提升收敛性和函数级定位质量。
3. 原始 SkillClaw skill 偏 ELF/CWE-120/PLT triage，对源码级 parser state-machine 漏洞支持不足。
4. 新增 `source-parser-state-machine-oob` 后，libxml2 结果从 5/10 提升到约 8/10，说明针对性 skill 能纠正原有分析偏置。
5. 现阶段最大短板不是“skill 是否能注入”，而是“注入后是否真的带来可验证能力提升”。因此后续研究重点应是可审计注入、case-level validation、skill-task 匹配度和外部验证反馈。

## 十一、后续实验建议

1. 优先跑通 `libxml2-2.9.4-cve-2017-8872` 的完整新框架链路：

```text
print_case_prompt -> Claude Code 输出 JSON -> score_agent_output -> run_dynamic_case -> build_result_record
```

2. 为 libxml2 接入稳定 PoC 或 ASan 构建，启用 `asan_command`。
3. 对 `source-parser-state-machine-oob` 的 bundle checker 继续增强，使其能自动输出候选文件、函数、guard mismatch 和置信度。
4. 后续论文表述应避免“SkillClaw 全面提升漏洞发现能力”，更适合表述为：

```text
LLM Agent 的 textual skill evolution 只有在 skill 与任务类型匹配、注入过程可审计、结果可由外部 validator 验证时，才能被证明对漏洞定位有实际提升。
```
