# Path consolidation audit — 2026-09-03

## Conclusion

The project can be simplified by enforcing clearer source-of-truth boundaries, but the
remaining major trees should not be physically merged in this round. Their meanings differ:
source code, runtime state, reproducible reports, paper inputs, and skill lifecycle storage
are separate concerns.

## Canonical boundaries

| Concern | Canonical path | Decision |
| --- | --- | --- |
| Implementation and tests | `skillclaw/`, `evolve_server/`, `evaluation/`, `tests/` | keep as code roots |
| Human-facing plans and operations | `docs/` | keep as the active documentation root |
| Current experiment conclusions | `reports/current/` | keep as the active report root |
| Raw and machine-generated run evidence | `runtime/` | keep as the reproduction/source-of-record root |
| Current paper workspace | `paper/package_20260824/` | keep as the canonical paper package |
| Source snapshot for provenance | `paper/materials_20260824/` | keep; it is a ground-truth snapshot, not a duplicate support tree |
| Skill lifecycle | `skillspace/source/`, `live/`, `share/`, `state/` | keep separate because runtime code depends on the distinction |

## Findings

- `paper/package_20260824/support/reports/` was mostly a duplicate export of
  `reports/current/`; the exact duplicates have now been removed. Three historical,
  content-different reports remain intentionally.
- `experiment_records/` contains a distinct 2026-07-28 feedback bundle. It is not byte-identical
  to `reports/current/skill_feedback_bundle.*` and has no active code consumer. It should be
  treated as a historical experiment input, not silently deleted in this round.
- `reports/publication/` is a generated publication-input area, while `reports/current/` is the
  active result area. Merging them would blur reproducibility and publication provenance.
- `reports/runs/` and `runtime/` both contain run-related artifacts, but the former is curated,
  report-facing confirmation evidence and the latter contains raw execution state. They should
  remain separate.
- `skillspace/.skillclaw_backups/` and the dated pull-stage directory are runtime snapshots/cache.
  They are candidates for a later explicit cache-retention policy, not a path merge.
- `skillspace/ablation_profiles/` is a controlled experiment input and is referenced by reports;
  it should not be folded into `source/` or `live/`.

The experiment label `server-inline-lexical` refers to the existing `inline` configuration mode;
it is not a separate code path or directory.

## Recommended next consolidation

1. Keep the four active roots visible at the repository entrance: `docs/`, `reports/current/`,
   `runtime/`, and `paper/package_20260824/`.
2. Add or maintain README boundaries for any directory that contains both generated and curated
   material; do not move data merely to make names look uniform.
3. After the catalog/server-catalog experiment is complete, review whether
   `experiment_records/` should be archived under `reports/archive/legacy_runs/` with a provenance
   note. That is a separate decision because it changes a historical input path.
4. Do not delete or merge `skillspace/share/`, `runtime/`, or `paper/materials_20260824/` based only
   on filename similarity.

## Backup/cache follow-up

The dated pull-stage snapshot was removed successfully. The `.skillclaw_backups/` directory was
then regenerated by the restart: `skillclaw/skill_hub.py` deliberately creates a backup before a
mirror pull and retains recent snapshots. It is therefore not a path-consolidation candidate;
removing it manually only causes it to reappear on the next pull. The current audit keeps
`skillspace/source/`, `skillspace/live/`, and the generated rollback snapshots intact.
