# FH451 Held-out Transfer Experiment (2026-08-26)

## 1. Experiment goal

This experiment checks a stricter question than ordinary blind-run scoring:

- whether a `candidate skill` generated by the current
  `blind run -> scoring -> feedback -> evolve` pipeline
- can improve a **different held-out blind case**
- instead of only helping on the source case that produced it.

This is a real remote-VM experiment, not an oracle-skill comparison.

## 2. Source / held-out setup

Source case:

- `benchmarks/cases/fh451-httpd-overflow-formQuickIndex.json`
- project: `FH451`
- CVE: `CVE-2026-3679`
- target binary: `vul_file/httpd`
- target functions: `formQuickIndex`, `sprintf`

Held-out case:

- `benchmarks/cases/fh451-httpd-overflow-formWrlExtraSet.json`
- project: `FH451`
- CVE: `CVE-2026-4534`
- target binary: `vul_file/httpd`
- target functions: `formWrlExtraSet`, `sprintf`

Why this pair was chosen:

- same device family
- same binary type
- same bug class (`buffer_overflow`)
- different vulnerable handler functions
- lower leakage risk than pairs that share the same vulnerable function

## 6. Interpretation

This experiment gives one strong engineering conclusion and one strong research
conclusion.

Engineering conclusion:

- the strict held-out pipeline is now runnable end to end
- candidate generation, freezing, remote held-out execution, scoring,
  confirmation, and result collection all completed successfully

Research conclusion:

- this first evolved candidate did **not** improve the held-out task
- all 9 runs still ended in `function_identity_miss`
- the candidate preserved or redirected the model into the wrong Tenda
  command-execution family, rather than pulling it toward the true held-out
  vulnerable function

In plain terms:

- we now have proof that the held-out experiment framework works
- we do **not** yet have proof that the current evolution result improves
  future unseen cases

## 7. Why this result matters

This is useful even though it is a negative transfer result.

It shows that:

1. the current evolve output can encode a real failure pattern
2. that encoded pattern can be replayed on a new task
3. the replay may still reinforce the wrong family-level heuristic
4. therefore, future work should focus not only on generating candidates,
   but also on constraining what kind of source evidence is allowed to shape
   a reusable skill

## 8. Next recommended direction

Before claiming positive transfer, the next held-out experiments should prefer:

- same project / same binary / same bug class
- different vulnerable functions
- source runs that are traceable
- source evidence that is less dominated by the same wrong drift family
