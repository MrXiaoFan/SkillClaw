## 四、阶段 2 · 系统完整性（闭环能否自证收益；含本轮代码审查新增修复）

### 2.A 已确认的代码级缺陷（本轮新增，P0/P1）
| # | 缺陷（代码位置） | 后果 | 修法 | 验收 |
|---|---|---|---|---|
| **D1** | `reject_ready` 无「总结果数达标」守卫（workflow.py:1186） | job 在 publish/reject 两阈值之间**永久 pending**（如 1 accept+2 reject 卡死）→ 是 34 pending 的源码 | 加守卫：`len(results)>=required_results` 时必须在 publish_ready/否则 reject 落定，不再无限挂起 | 线上 pending 清空、不再复涨 |
| **D2** | 默认 `publish_mode=direct` 绕过 gate（config.py; workflow.py:1374） | 若某次未走 start_evolve.ps1 则技能无门控直接发布 | 启动路径统一 validated；config 默认改 validated 或加显式校验 | 所有发布均经 validated |
| **D3** | gate 是 tool-free 文本重放（replay_gate_worker.py:145-165） | 验证「给证据能否写对答案」，非「带 skill 从零重找洞」→ gate 通过≠有效 | 增加 real_rerun 覆盖度；论文诚实标注 | 论文边界写清 |
| **D4** | gate 不覆盖 description→检索回归（skill_manager 关键字检索） | 改坏 description 被接受→发布后检索失效（v8 真实负例） | gate 增加「改后 description 重新检索仍能选中」断言 | 检索回归用例通过 |
| **D5** | 无发布后效果追踪 / 无回退（_resolve_and_upload） | 只能证「发布发生」非「发布后变好」 | 加 hold-out 前后对比 + 回退机制 | 拿到前后对比证据 |
| **D6** | 反馈归因 observational（workflow.py:290-293; assess_skill_relevance token 匹配） | 进化决策建在弱因果证据上 | 加强 trajectory 级对齐 或 论文标注限制 | 归因口径明确 |
